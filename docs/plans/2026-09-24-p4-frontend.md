## 关键设计决策

1. **documents 上传走「写文件 + 复用增量管线」**：POST 收 multipart 的 .md 文件 → 校验扩展名/可解析/`doc_id` 不与现有文件冲突（同 doc_id 不同文件会互踩主键）→ 写入 `data/corpus/` → 跑 `IndexPipeline.run()`（增量，只嵌入新块）。同名文件覆盖 = 更新语义，走 rebuild。删除 = 删文件 + `run()`（管线自动清块 + manifest 移除 + BM25 全量重建）。**不为上传/删除单独写索引逻辑，业务零拷贝。**
2. **索引操作加 asyncio.Lock**：`IndexPipeline.run()` 内部 BM25 全量重建 + Chroma 增删，非并发安全；上传/删除/reindex 共用一把锁，与在线检索读路径互不干扰（BM25 build 原地换新索引对象）。
3. **GET /api/documents 状态对比**：manifest 记录 × 磁盘实际 md5 对比，标 `synced / stale（文件变更未重建）/ pending（新文件未索引）/ missing（manifest 有但文件已删）`——前端「增量状态」列直接展示。
4. **SSE 反代用通配 Route Handler**：`web/src/app/api/[...path]/route.ts` 把 GET/POST 原样转发 `http://127.0.0.1:8766`，`response.body`（ReadableStream）直接作为新 Response body 透传，`content-type: text/event-stream` 原样带回。一个文件覆盖所有接口，不为每个路由写转发。
5. **前端 SSE 消费用 fetch + ReadableStream 手动解析**：`EventSource` 不支持 POST；按帧解析 `event/id/data`，事件处理：`status(retrieving)` 显示检索中 → `retrieved` 暂存 items（角标+抽屉数据源）→ `answer_delta` 追加打字 → `status(citation_retry)` **清空已渲染文本**重新接收 → `done` 定格 citations/citation_ok/refused/usage/latency。
6. **`[n]` 角标映射**：编号 n 对应 `retrieved.items[n-1]`（后端契约），正则切分答案文本渲染可点击角标，Popover 展示文档标题/章节路径/生效日期/版本/块原文；`done.citations` 里未出现在最终 answer 的编号不展示角标（以最终文本为准）。
7. **状态管理零依赖**：React state + 少量自定义 hook（`useChatStream`），不引 Zustand/Pinia 类库。

## Task 拆分

### Task 1 后端 `/api/documents` 路由 + 测试
- `app/api/routes.py`（或新建 `documents.py`）追加：
  - `GET /api/documents`：manifest.all() + 磁盘对比 → `[{doc_id, path, md5, chunk_count, version, valid_from, valid_until, indexed_at, status}]`
  - `POST /api/documents`（multipart .md）：校验（扩展名 / frontmatter 可解析 / doc_id 冲突）→ 写 corpus → 锁内 `pipeline.run()` → `{doc_id, added, total_chunks}`
  - `DELETE /api/documents/{doc_id}`：404 保护 → 删文件 → 锁内 `run()` → `{removed: true, report}`
  - `POST /api/documents/reindex`：锁内 `run()` → `{added, rebuilt, skipped, removed, total_chunks}`
- `tests/test_documents_api.py`：mock 组件覆盖 列表/上传/重复 doc_id 拒绝/删除/reindex/非法扩展名
